⚙️ How It Works

Layer 1 — DNS
Custom Domain
Wildcard A record *.yourdomain.com points to your VPS IP. All subdomains resolve to the same server.
Layer 2 — Firewall
UFW
Only ports 22 (SSH), 80, 443, and 81 are open. All other ports are blocked by default.
Layer 3 — Brute Force
Fail2Ban
Monitors SSH and web logs. Automatically bans IPs that exceed login failure thresholds using Docker-aware iptables rules.
Layer 4 — Proxy
Nginx Proxy Manager
Routes each subdomain to the correct container by name. Handles Let's Encrypt SSL for all services automatically.
Layer 5 — Containers
Docker (npm_default)
All services run isolated in Docker. Reachable only through NPM — no container is directly exposed to the internet.

🧩 Services

Service Subdomain Purpose
Nginx Proxy Manager npm.yourdomain.com SSL gateway and routing hub — admin panel for all proxy config
Nextcloud AIO nc.yourdomain.com Self-hosted Google Drive — files, calendar, contacts sync
Vaultwarden vault.yourdomain.com Self-hosted Bitwarden — password manager for all devices
Immich photos.yourdomain.com Self-hosted Google Photos — photo and video backup with AI features
FileBrowser files.yourdomain.com Web-based file manager to browse and manage VPS storage
Portainer portainer.yourdomain.com Docker container management dashboard — monitor, start, stop containers

📐 The Golden Rule

Every container joins the npm_default Docker network and uses expose: — never ports:. NPM is the only entry point from the internet. No container is directly reachable externally. 

networks:
  npm_net:
    external: true
    name: npm_default   # must be this exact name — always
